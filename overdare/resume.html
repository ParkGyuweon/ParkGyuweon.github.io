추천 평가 설계

추천 결과를 비교하기 전에 데이터 범위부터 정리했습니다.

문제

원본 리뷰에는 사용자 속성이 비어 있는 행이 있었고, 피부톤 표기는 14종으로 나뉘어 있었습니다. 이대로 집계하면 같은 사용자군이 여러 값으로 나뉘어 평가될 수 있었습니다.

데이터 정제 기준
  • 사용자 속성 4개가 모두 채워진 Sephora 리뷰 844,865건과 스킨케어 상품 200개로 분석 범위를 한정했습니다.
  • 피부톤 14종을 5개 버킷으로 정규화해 집계 단위를 통일했습니다.
feature 분리 설계
  • 성분, 피부 고민, 카테고리, 브랜드를 담은 148차원 상품 벡터와 사용자 속성 친화도 테이블 4,000행을 분리했습니다. 상품 유사도와 사용자별 선호도를 다른 기준으로 계산하기 위해서입니다.
holdout 검증 구조
  • holdout_a와 holdout_b를 각 2,000명으로 분리했습니다. holdout_a는 모델 선택에, holdout_b는 선택한 모델 확인에 사용했습니다.
  • 평가용 행동 로그에서는 추천 노출 결과와 hidden preference를 분리했습니다. 추천 결과가 다시 정답으로 사용되지 않도록 하기 위해서입니다.
결과

이 기준으로 평가한 팀의 CBF + CF + LTR 결합 모델은 Recall@10 42.15%, 43.15%를 기록했습니다. 모델 결과는 팀 성과이며, 데이터 범위와 검증 구조 설계를 담당했습니다.

생성 결과를 후처리하지 않도록 추론 방식을 바꿨습니다.

문제

모델이 생성한 문장에서 답을 다시 추출하는 방식은 문장 형식에 따라 결과가 달라질 수 있었습니다. 정답이 맞아도 파싱이 실패하면 평가 결과가 흔들렸습니다.

한 일
  • InternVL2-8B를 4-bit QLoRA로 학습하고, 정답 토큰에만 loss가 계산되도록 label masking을 구성했습니다.
  • 생성 문장에서 답을 추출하는 대신 a/b/c/d 토큰의 logits를 직접 비교하도록 추론 방식을 바꿨습니다. 결과가 네 선택지 중 하나로 결정되도록 제한했습니다.
결과

parsing error를 0건으로 줄이고 추론 속도를 약 2배 개선했습니다.
